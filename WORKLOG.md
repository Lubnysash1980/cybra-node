# CYBRA — робочий журнал і список задач

Останнє ручне оновлення: 2026-11-28
Гілка: `feature/cybra-process-automation-20261128`

Цей файл — головний handoff для наступного чату/сеансу. Перед змінами прочитати його разом із [поточним станом](state/work_status.json) і [планом розгортання](docs/PROCESS_AUTOMATION_PLAN.md).

## Архітектура
- **Oracle VPS** — цільовий постійний runtime, 24/7; підключати лише після перевірки доступу та конфігурації.
- **GitHub Actions** — CI, scheduled repository checks, підготовка/контроль deploy. Runner тимчасовий і не є сервером 24/7.
- **Termux** — локальна панель/адміністрування та резервний клієнт; не є обов'язковим для роботи VPS.
- **Namecheap** — роль ще не підтверджена; використовувати лише реально доступні функції (DNS/домен/hosting/VPS).

## Правила безпечного запуску
1. Не запускати одночасно systemd, PM2 і nohup як незалежних supervisors для того самого процесу.
2. На Oracle VPS обрати один головний supervisor; cron/systemd timers — лише для періодичних задач.
3. Не запускати автоматичне npm install/dedupe/cache clean у робочому дереві без backup, lockfile diff і погодження.
4. Не затирати локальні зміни під час deploy; deploy workflow має зупинятися на dirty working tree.
5. Невідомий стан позначати як `not_checked`, а не `online`.
6. GitHub Actions schedule — періодичний контроль, не постійний daemon.
7. Секрети, токени, приватні ключі та PM2 dump з environment не комітити в GitHub.
